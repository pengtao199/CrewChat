# 依赖与选型

## 适用范围

新增依赖、选择开源实现、升级现有库、遇到网络受限时。

## 目标

不造已有的轮子；新增依赖前先确认它解决的是真问题，且不与现有栈冲突。

## 原则

- **先调研后动手**：任何非平凡层次（协议转换、流式、持久化、UI 外壳、编排循环）先搜索成熟开源实现，比较后说明选谁、为什么。
- **优先官方 SDK**：厂商官方库 > 官方 CLI > 社区库 > 自研。
- **先内省再假设**：已安装的包往往比文档提供更多能力，先看它的导出与签名再决定是否外包一层。
- **版本兼容是硬约束**：接入前确认目标版本与本机安装的版本匹配，不匹配时明确记录绕过方式。

## 具体规则

- 新增依赖前，先确认现有依赖是否已覆盖（例如流式、并发、重试）。
- 记录选型结论：写进 `AGENTS/` 相应规则文件或提交信息，说明候选、取舍与依据。
- Python 依赖用 `uv add`；前端依赖在 `codeg/` 下用 pnpm（`packageManager` 锁定版本）。
- 依赖体积会进入最终产物，前端尤其注意（曾因 `monaco-editor` / `mermaid` 等体积大而剔除与保留页面无关的包）。

## 已固化的第三方源码（vendored）

- **Codeg** → `codeg/`（Apache-2.0）。协作工作台（Next.js 前端 + Tauri/Server 后端）的二次开发基座。
  - 排除 `.git/` 与 `docs/images/`；取舍与升级方式见 `codeg/NOTICE.md`。
- **CCR（claude-code-router）** → `ccr/`（MIT）。**legacy 回退**；运行时已由 `model-layer/` 取代。
  - 排除 `.git/`、`blog/`、`cdn/`；取舍与升级方式见 `ccr/NOTICE.md`。
- **模型层** → `model-layer/`（自有 Rust 代码，不是 vendored 基座）。

## 网络受限

- 遇到下载/安装因网络失败（DNS、TLS、超时、限速），**停止并报告**：原始错误、尝试过什么、建议下一步。
- 不自行切换镜像、代理、VPN 或凭据；换源需要明确授权（本项目前端使用国内镜像即经授权）。
- 不反复重试同一请求。

## 禁止项

- 不在未调研的情况下手写协议客户端、事件循环、UI 外壳、解析器。
- 不为"以后可能需要"引入依赖。
- 不把有冲突的依赖强行装进同一环境（曾遇 `litellm[proxy]` 与 Chainlit 的 mcp 版本冲突，结论是拆进程）。
- 不静默降级：依赖不可用时要么显式报错，要么有明确的设计说明。

## 检查

- 这个能力现有依赖里真的没有吗？我查过它的导出了吗？
- 选它的理由能写成一句话吗（对比了什么）？
- 它与现有依赖的版本约束冲突吗？
- 选型结论记在哪了？
