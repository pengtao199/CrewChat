# 界面与文案

## 适用范围

改动 `AgentOS/` 下的界面（SwiftUI）及其交互、文案、样式时。

## 背景

界面只有 `AgentOS/` 的 macOS 原生壳（SwiftUI）。边界：**界面只做展示与交互，判断归核心**。

## AgentOS 界面（`AgentOS/`）

目标：像一个平静的 macOS 团队工作台——谁在干活、干了什么、要不要批准，一眼可见。

**状态归属**

- 视图渲染状态、发送意图；不发请求、不读文件、不解码 JSON。
- 屏级状态归 `@Observable` 视图模型；连接与运行时状态归 `Domain` 端口背后的 `Core` 实现，视图只观察。
- 同一个真相只有一个持有者；不允许多个视图模型各自缓存同一份数据。

**布局**

- 侧栏：项目 / 工作区、会话列表。
- 中间：会话流（消息、流式内容、工具调用、委派卡片）。
- 右侧检查器：选中对象详情、用量、事件、审批。
- 工具栏：核心连接状态、运行 / 取消、当前会话归属。

**规则**

- **只用系统控件，不造组件**：不建自有设计系统（不定义品牌色、字体、圆角、间距令牌）。允许 `NavigationSplitView` / `NavigationStack` / `List` / `Table` / `Form` / `Section` / `LabeledContent` / `ContentUnavailableView` / `.searchable` / `.toolbar` / `.inspector` / `.sheet` / `.alert` / `.confirmationDialog` / `.popover` / `ProgressView` / `Gauge` / `Menu` / `Picker` / `Toggle` / `TextField` / `Table`；需要而清单里没有的，先用最接近的系统控件，别自绘。
- **禁止**：自绘控件、用 `onTapGesture` 冒充按钮、自造 Tab / 侧栏视觉、拼自定义图标集、自定义配色。
- **颜色用语义色**（`.primary` / `.secondary` / `.green` / `.orange` / `.red` / `.tint`），不定义品牌色。
- **空态统一 `ContentUnavailableView`**；危险操作走 `confirmationDialog` 并写清后果。
- **侧栏折叠**：每个工作区一个 `Section(isExpanded:)`（macOS 14+），初始全折叠；折叠状态进 `@SceneStorage`。不用自绘 disclosure。
- **inspector 边界**：最多 3 个 `Section`；只放次要信息；不放主操作（发送 / 取消 / 审批）；不重复主栏已在显示的信息；默认隐藏、记住上次开合；快捷键 ⌘⌥I。
- **设置页统一用主从骨架**：`HSplitView` 左侧窄列表（200–320）+ 右侧宽详情（≥380）；`+` 固定在工具栏尾部；选中即编辑；保存 / 删除统一放在详情底部的操作行。三态互斥：**有错误就不显示空态**，未选中显示「在左侧选一项」，列表为空显示添加入口。
- **工具栏只放当前栏的动作**：侧栏放「添加工作区」，主栏放「运行 / 取消 / inspector」，不把全局动作堆到窗口工具栏。**唯一例外**：全局「设置」入口（齿轮 / 返回工作区）固定在工具栏尾部，与 inspector 开关同区。
- **设置是窗口内的一种模式，不是独立窗口**：点工具栏齿轮或 ⌘, → 左栏换成设置项列表、右栏换成该设置的详情；工具栏尾部变成「返回工作区」。不使用 `Settings` scene、不开独立窗口，也不在侧栏底部或页面里再造入口。
- 状态可见：每个参与协作的 Agent 的状态（排队 / 思考 / 流式 / 等待工具 / 阻塞 / 完成 / 失败）在会话里直接可见，不用打开日志。
- 审批就近：权限请求出现在对应会话与工具调用旁，不弹全局模态。
- 错误就近：错误挂在出错的会话 / Agent / 工具调用上。
- 不做营销式落地页；首屏就是工作台。
- 视图保持小；不写解释性长注释与同义注释；不把服务调用写进 `body`；不在视图里做状态判定。

**文案**

- 用户可见文案走 String Catalog（`Localizable.xcstrings`），不写死在视图里。
- 先只登记 `zh-Hans`；补齐当前界面后再说第二种语言。
- 键名表达产品含义（`session.toolCall.approved`），不表达当前中文措辞。
- 提供商名、模型 id、URL、文件路径是数据不是文案，不进 String Catalog。
- 核心返回的 `i18n_key` 优先于核心的英文 `message`（见 `agentos-transport.md`）。

检查：每个显示出来的状态，唯一真相源清楚吗？用户能看到「谁在工作、为什么」吗？能取消、能批准吗？新增文案登记进 String Catalog 了吗？

## 通用

- 不为「以后可能需要」新增依赖或视觉体系（见 `AGENTS/dependencies.md`）。
- 用户可见的错误必须是可操作的：说清哪一层出的问题与下一步。
